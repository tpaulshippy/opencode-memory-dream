# Talk Grounding Rituals

Meta-rituals from the talk's own SKILL.md. Every claim about
the talk must trace to a citable line, never to memory alone.

## Grounding rule

Procedure: outline the claim → locate the transcript section →
cite a verbatim quote + line reference. Never paraphrase as
a quote. If no supporting line exists, write the fallback:
'talk doesn't address this' — then label the idea [not from talk].

Attribution rule: speaker labels in auto-transcripts are
unreliable, so never cite a name from a label. Write
"the speaker said..." and quote the words, not the attribution.
Cross-reference any named addressees against the participants list;
questioners with no reliable label are cited as "a questioner".

## Audit workflow

Walk the 4 principles one by one against the artifact:

1. Quote the principle's key line(s) verbatim.
2. Find where the artifact implements (or should implement) it.
3. Verdict per principle: covered / partial / missing.
4. List missing lines as follow-up tasks with section cites.

The 4 principles live in the talk outline; the audit walks all
four even when only one seems relevant — partial coverage
hides in the "obvious" ones.

## Draft workflow

Drafting from the talk: outline first from section headers,
then fill each section with verbatim quotes before adding any
original prose. Original prose is marked [not from talk].
No section ships with zero quotes.

## Teach workflow

Teaching the talk: state the idea in one sentence, play the
verbatim quote, then explain. Quote first, interpretation
second — learners must hear "the speaker said..." before
hearing what you think it means.

## Apply workflow

Apply workflow (how would the speaker tackle <X>?): take a new
problem <X> the talk never addressed, re-read the relevant talk
section, then reason out loud about what the speaker would do
given their stated principles — marking every step beyond the
transcript [not from talk]. Never present the application as
something the speaker said; close with what the transcript
actually covers vs what you inferred.

## Sources

Transcript §§ in this repo resolve against the upstream talk repo files —
https://github.com/AINativeDev/aidevcon-2026-ldn/tree/main/talk-lamis-context-engineering-dreaming:
`transcript.md` (§§ + line refs), `outline.md` (section map), `quotes.md` (anchor lines).

## Proactive-citation workflow

When answering questions the talk covers: lead with the
verbatim quote + line cite, then the short answer. If the
question goes beyond the transcript, answer normally but end
with: 'talk doesn't address this' for the beyond-scope part. Never
let a paraphrase wear quotation marks.
